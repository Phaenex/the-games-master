## The one thing to understand about this codebase

**Everything here has passing tests over it. That is not the same as working.**

Seven defects were found today. Every one had green tests. None was found by a test:

- The prologue did not play for a player who obeyed the letter
- The estate house had no collision at all
- Four of six player spawns were inside furniture
- Nothing from Phase A1 or A2 was in any build
- The title screen threw 9,906 exceptions in twenty seconds
- The drive's mud had a **zero** blue channel, so no light could ever cool it
- Six rooms were lit by HDRP's default sky, not by their own lamps

Each was found by **building it, running it, and looking at the result.** Several only after Nick
looked at a live window and said it was wrong.

If you take one thing from this handoff: the tests here tell you the code runs. They do not tell you
the game works, and they cannot tell you it looks right.

## Process that worked, in priority order

**1. Interrogate the scene, not the code that writes it.**
Four wrong answers on the orange ground, all from opening the file that sets a value and reading it.
Every reading was accurate. Three were about surfaces the camera was not looking at. The fifth
attempt raycast down the actual route and reported the real renderer, material, shader and colour —
found it in one pass. `GmGroundToneProbe` is that query; extend it rather than rewriting it.

**2. Move an input 20x. If the output does not move, you have the wrong lever.**
Three careful fixes for the room lighting all failed. Cutting the lights 23x and watching nothing
happen found the cause in one run. Use this as the *second* move, not the fourth.

**3. Break every new guard on purpose before trusting it.**
Every guard added today was sabotaged first and watched go red. A check nobody has seen fail is a
check nobody should believe. The meta-gate (`scripts/test-harness-integrity.mjs`) exists to enforce
this and needs **both** directions per case — rejects bad input AND accepts good, or "always fails"
scores as healthy.

**4. Look at it. Every time. Before saying it works.**
The colour-cast rule I built measures hue, so by construction it cannot see "correctly balanced and
far too bright". It passed a washed-out night at 1.35. Nick caught it in a live window. For anything
visual, look FIRST — the numbers are a floor, never the verdict.

**5. Sweep the class, not the instance.**
A gate reports the instances it can reach; it never reports the size of the class. Fixing the three
floor overlays a spawn probe named would have left a fourth identical one that no spawn test could
ever see.

### Traps that each cost a cycle today

- **Run Unity tasks with the sandbox disabled.** Otherwise `unity-cli` dies on `spawnSync ps EPERM`
  before Unity launches. Reads like a test failure; is not one.
- **Never chain two `unity-cli` runs in one shell line.** The previous editor has exited but not
  released the project. Wait: `until ! pgrep -f "Unity.app/Contents/MacOS/Unity.*<project>"; do sleep 5; done`
- **Never trust `cmd | tail` exit codes.** Bit me again today.
- **Read the log the run actually wrote.** `rebuild wend-hill-prologue` writes `cli-rebuild.log` with
  no scene prefix (it is the default scene); every other scene gets `cli-<scene>-rebuild.log`. I read
  a two-hour-old prefixed file and nearly mis-attributed a correct result.
